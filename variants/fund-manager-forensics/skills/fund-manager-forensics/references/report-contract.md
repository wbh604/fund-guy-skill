# 报告合同

## 首页

第一屏是基金经理颁奖台：真实肖像、像素跳舞形象、基金和经理姓名、主封号、`可以买/不能买` 印章、机构结论、三座奖杯、证据截止日。

三座奖杯只回答：最强本事、最大硬伤、机构态度。首屏不展示模型公式。

## 顺序

1. 购买判决：三条理由、适合谁、翻案条件。
2. 机构投票：四席意见、冲突、首席裁决、仓位和否决项。
3. 人物底牌：24 项 People、能力形成、哲学、行为 DNA、错误与家庭公开边界。
4. 牛熊和 Alpha：任期、跨周期、Alpha/Beta、运气、可复制率。
5. 赢票输票：盈利最多、亏损最多、经理满意票及 B/H/S 图。
6. 规模、抱团、资金、持有人、合规。
7. 完整取证暗柜：45 项、24 项和来源。

独立决策区必须并排显示“敢不敢和同事不一样”和“不一样时有没有赚到钱”，不得合并。证据不足时直接列出还缺的公司产品、季度和主题合同，不用空分数装精确。

## 文案

- 先判，再证。
- 一个模块：一个封号、一句判词、三条证据、一条反证。
- 不用“综合来看、值得关注、长期视角下、一方面另一方面”。
- 不用伪精确投票、Alpha 百分比或置信度。
- 娱乐封号只能来自行为证据，例如“规模受害者”“熊市保安”“抱团的神”；不能取笑外貌、地域或隐私。
- 内部编号不得进入界面：M01、P11、A01、评审角色键和事件码只留在 JSON。
- 来源显示来源报告全名、发布日期、页码或段落和“打开原文”。
- 状态写“公开资料确认 / 根据公开资料推算 / 证据还不够 / 公开资料未找到”。
- 交易动作写“买入或加仓 / 继续持有 / 减仓 / 完整报告确认退出”。
- 专业概念先写“敢不敢和同事不一样”“不一样时有没有赚到钱”等中文，必要时只在中文后用括号补充专业词。

## 图表

持仓图只画披露事件；页面直接标“买 / 持 / 卖”，估算区间和实际成交未知要同屏可见。

战役回放使用真实 K 线。新闻用精确日期，经理动作使用时间区间；同时显示经理时钟与公众时钟。新闻、动作、原话、结果分层呈现，不能用新闻替经理解释买卖动机。关键事件可展开来源全名、发布日期和原文。

数据与证据默认折叠，点击才看来源、报告期、页码和计算方法。关键缺口不能折叠隐藏。

## 最低输出

- `buy_now` 布尔值、中文标签和由首席核保写出的案例专属传播句；渲染器不得写死结论。
- 机构结论、建议仓位、否决项、翻案条件。
- 当前经理与共同经理任期。
- 45/45 与 24/24 覆盖。
- 至少一只赢家和一只输家。零张满意票也可完成 Deep，但必须保存检索日志，在 `manager_approved` 写入“未发现经理本人明确点名”的零结果记录，并把行业描述映射出的股票单列为候选，绝不能升级成明牌。
- 数据截止日和非个性化投资建议声明。
