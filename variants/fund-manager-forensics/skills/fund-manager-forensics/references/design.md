# 基金经理照妖镜 · 设计总纲

> 本文件是整个产品的"设计宪法"。所有实现(SKILL.md 流程、前端、数据管线)都必须能从这里追溯到理由。
> 每一节讲清楚两件事:**我们做什么** 和 **为什么这么做**。

---

## 一、核心理念

### 1.1 主角是基金经理,不是基金

> **以基金经理为主角,基金作为他的长期行为记录。**

基金经理是主角，基金不是主角。

- 基金净值、持仓、Alpha、抱团、机构资金,全都是**反向证明这个经理是什么人、有什么能力、有什么弱点**的证据
- 不是"先看基金,顺便介绍经理",而是"先搞清楚这个人,再判断他的钱能不能交"

### 1.2 一句话定位

> **他和公司主流观点不一样的时候,有没有反复证明自己是对的。**

"所有人都看对了白酒,他也买白酒赚了钱" 和 "所有人都在白酒,他独立发现另一个赛道并持续创造超额" —— 在评价一个人的投资能力时,不是一回事。这个产品存在的唯一理由,就是**把这两种人分开**。

### 1.3 核心公式

```
Non-Consensus + Correct + Repeatable = 独立决策 Alpha
```

三个条件缺一不可:
- 只有 Non-Consensus = 有主见,但主见没价值,可能只是瞎搞
- Non-Consensus + Correct 但不 Repeatable = 运气
- 三者齐备 = **独立型 Alpha 经理**,值得把钱交出去的人

### 1.4 面向谁

**假设读者不知道"买基金要看基金经理"。** 不是机构投研,是被推荐了一只基金、想知道该不该买的人。

这句话决定了所有设计:
- 界面全中文,英文术语只做括号补充
- 判词用大白话,不用研报腔
- 严肃性由数字保证,不由排版保证 —— 所以"对战擂台""判决印章"这类好玩的组件不会因为"不够严肃"被删

## 二、核心方法论:独立决策 Alpha

### 2.1 为什么必须对比"公司其他人"

判断"敢不敢不一样",需要一个基准:**公司主流观点**(House Consensus)。没有它,"不一样"无从定义,也分不清"独立"和"瞎搞"。

### 2.2 House Consensus 构建(两条硬规则)

1. **必须排除目标经理自己的产品。** 否则他越极端,共识越向他靠,Divergence 被系统性低估。管理规模占公司 20%+ 的经理,这个偏差足以反转结论。
2. **必须同时算两套权重:**
   - AUM 加权 —— 反映公司真金白银的方向
   - 经理等权 —— 每位经理一票

   为什么两套:如果一家公司靠一个 800 亿的明星经理拉出"白酒共识",但另外 20 个经理人均 25 亿其实分散配置,那这个"共识"就是**伪共识** —— 少数大基金刷出来的表面共识。计算 Divergence 默认用经理等权(才代表"公司里的人怎么想"),AUM 口径对照展示。

### 2.3 双分数,永不合并

| Independent Thinking | Independent Alpha |
|---|---|
| 敢不敢跟同事不一样(持仓差异度) | 不一样的时候赚不赚钱(分化后真实回报) |

**两个分数永远分开展示。** 高 Thinking + 低 Alpha = "有主见,但主见没价值",必须明确标出来。合并成一个"独立性 82 分"会掩盖这个关键区分。

### 2.4 排除假独立(Mandate 调整)

全公司都买白酒,但他管的是科技主题基金 —— 他不买白酒是合同规定,不是独立判断。必须在算 Divergence **之前**,把合同允许范围内的偏离扣除,只算真正的主动偏离。

### 2.5 核心验证:Contrarian Alpha

Divergence 高不算本事,**分化之后赚钱才算**。把过去 ≥20 个季度按 Divergence 高低分组,比较各组的未来 12M 超额。如果高分化期的超额显著更高,才证明"独立判断是真资产";反过来,高分化期更差 = **独立性是负资产**,同样重要,必须如实报告。

### 2.6 战役档案(Independent Calls)

把"和公司对着干且维持 ≥2 季度"的重大决策记为一场战役,以 12M 后相对 House 的超额判胜负。**败仗必须和胜仗同等篇幅、同等卡片尺寸、按时间混排。** 只挑赢家秀 = 整个报告失去可信度。

### 2.7 Idea Origination

比"公司都买白酒他买半导体"更牛的,是"**他先买半导体,半年后整个公司跟着买**"。他是公司的 Alpha 源头(Idea Generator)还是跟随者(Idea Consumer),直接决定"离开这个平台还值多少钱"。

### 2.8 影子经理

反向排查:他是否长期滞后跟随某位核心经理(滞后 1-2 季度高度重合)。命中即独立决策能力存疑,封顶评分。

### 2.9 公司层面独立性

同一套方法上移一层:这家公司相对全市场公募是否独立?区分"经理独立"与"公司整体抱团" —— 他在公司内独立,但公司整体挤在消费里,那他可能只是在拥挤赛道里换了个车道,团灭时一样跑不掉。

## 三、十二步流程

| 步骤 | 内容 | 一句话 |
|---|---|---|
| 1 | 身份识别 | 锁定基金、经理、公司产品清单 |
| 2 | 任期切割 | 前任业绩混入现任评价 = 分析作废 |
| 3 | 经理个人尽调 | 职业路径 / 哲学 / 行为 DNA / 造神检测 / 错误档案 |
| 4 | 历史行为重建 | 逐季持仓、买卖、集中度、换手 |
| **5** | **独立决策取证** | **House Consensus / Divergence / Contrarian Alpha / 战役 / Idea Lead(核心)** |
| 6 | Benchmark 工程 | 合同 / 同行 / Shadow / House 四层基准 |
| 7 | Alpha 尸检 | 收益拆到市场/风格/配置/选股/择时 |
| 8 | 能力验证 | Buy/Sell/Sizing/Holding/择时 评级 |
| 9 | 组合与风险 | 隐藏集中度 / 情景压力 / Regime 天气 |
| 10 | 容量·资金·平台 | 还能装多少钱 / 谁在买 / 离开平台还行不行 |

**STEP 5 是灵魂,其他步骤都是它的证据链。** 前后台分离:后台 12 步,前台只有 6 个 Tab。

## 四、评分框架

### 4.1 一级权重(为什么经理个人最高)

| 模块 | 权重 |
|---|---:|
| **基金经理本人（Manager / People）** | **28%** |
| 投资优势与主动收益（Investment Edge & Alpha） | 20% |
| 组合构建（Portfolio Construction） | 11% |
| 风险管理（Risk Management） | 11% |
| 市场适应与可重复性（Regime & Repeatability） | 10% |
| 容量与流动性（Capacity / Liquidity） | 8% |
| 利益一致与治理（Alignment / Governance） | 7% |
| 平台与流程（Platform / Process） | 5% |

**Manager 占 28% 是因为本产品的前提:** 对主动基金,人在能力在,人走能力走。基金评分必须体现"这本质上是这个人的基金"。

### 4.2 Manager 细分:独立决策独占 8 分

独立决策 Alpha 是单项最高的 8 分,拆成 Thinking 2 / Alpha 3 / 胜率赔率 1.5 / Idea Origination 1.5。**Thinking 高但 Alpha 为负时,该项按 Alpha 折算,封顶 2 分** —— 有主见但主见没价值不加分。

### 4.3 评级映射与证据置信度

| 总分 | 评级 | 用户结论 |
|---:|---|---|
| 85–100 | A+ / A | 可以买 |
| 70–84 | A- / B+ | 可以买，但要盯住风险 |
| 55–69 | B / B- | 先观察 |
| 40–54 | C | 不要加仓 |
| < 40 | D | 回避 |

证据置信度(High/Medium/Low/Insufficient)低时**评级上限 B+**,不论算出多少分。数据不够不能硬下结论。

## 五、稀有度体系(双维判定)

稀有度回答的问题不是"多强",而是**"多强 × 多少人知道"**。两个维度:

### 5.1 实力档(客观算)

直接用 IC 总分映射:

| 实力档 | 总分 | 手感 |
|---|---|---|
| **SSR** | ≥ 85 | 顶尖实力 |
| **SR** | 70–84 | 明确有本事，也有约束 |
| **R** | 55–69 | 一般或有明显短板 |
| **N** | < 55 | 实力不达标 |

### 5.2 稀缺度(agent 主观判定)

**"小众" = 知道他的人少 + 愿意把钱给他的钱少。** 为什么必须 agent 主观判,不能纯算数:

- AUM 和机构占比只能算"冷启动线索"(12.5 亿 → 偏小;机构 5.3% → 偏散户)
- 真正的"小众感"藏在文字和圈层信号里:
  - **媒体热度**:搜他名字,是新闻访谈一堆,还是只有基金公告?
  - **公司推不推**:有没有把他做成明星产品(海报/访谈/路演)?
  - **圈内口碑**:卖方研报覆盖吗?基金博主提吗?有没有"发现宝藏经理"这类帖子?
  - **持有人质感**:机构重仓(圈内认可、不稀缺)还是散户小额自发堆起来(没人推、真小众)?

agent 读完证据,给 0–100 稀缺度 + **一句可核实的理由**。这是本产品最有"人味"的判定 —— 每个数字背后都有 agent 的真实观察。

### 5.3 合并矩阵

| 实力档 | 稀缺度 | → 最终稀有度 |
|---|---|---|
| SR(78分) | 极度稀缺(70+) | **SSR** |
| SR(78分) | 大众(20) | SR |
| SSR(85+) | 极度稀缺(70+) | **UR** |
| SSR(85+) | 大众 | SSR |
| R(55-69) | 极度稀缺 | SR 或 R |

**同样的实力,越少人知道 → 越稀有。** 因为"没人知道"意味着还没被买贵、还有超额空间;"全市场都在买"意味着已贵、超额被瓜分。

### 5.4 降档 / 保底(硬规则)

| 条件 | 处理 |
|---|---|
| 证据置信度 Low / Insufficient | 上限 R |
| 独立 Alpha ≤ 0 | 上限 R |
| 造神检测红旗 | 直接 N |
| 无负面 + 剔Top3仍正 + 赔率>2 + 证据High | 至少 SR |

**虚构示例：经理甲 78 分，实力 SR；稀缺度 70，最终为 SSR。** 升档来自稀缺度，实力分仍是 78。

## 六、造神检测

### 6.1 查什么(9 项)

| 项 | 通俗问法 |
|---|---|
| 甩锅跑路 | 下跌期有没有把亏损基金转给新人 |
| 摘桃子 | 是不是等别人做出业绩才接手 |
| 藏尸体 | 有没有失败产品被清盘藏起来 |
| 蹭业绩 | 挂名共管是否被算成个人战绩 |
| 高位圈钱 | 是否趁行情好猛发新基金 |
| 年底冲榜 | 是否为排名年末赌一把 |
| 人设造假 | 嘴上说的和实际买的是否一致 |
| 偷换尺子 | 是否悄悄改了比较基准 |
| 利益冲突 | 亲属是否在关联机构掺和 |

主证据是**经理变更公告 + 当时市场涨跌对照** —— 甩锅这事,只有把变更时点和跌幅并列才看得出来。自动化线索:下跌期标题含"增聘"且接任者从业 < 2 年 → 红旗候选。

### 6.2 边界(硬规则)

只查**关联方与利益冲突**:亲属是否在关联机构任职、是否持有重仓股、佣金是否异常。**不采集**配偶姓名、职业、学历等私人传记信息 —— 那是没有公众身份的私人个体,既查不到可靠公开记录,也没有投资含义。披露不够时只能写"未发现",不能写"不存在"。

## 七、数据策略

### 7.1 优先 akshare,判断归 agent

五接口覆盖 2.5/3 样核心数据(逐季持仓 / 经理变更公告 / 全市场横截面 / 经理-产品映射 / 净值)。**半年报年报全持仓必须自己解析 PDF。**

### 7.2 agent 必须判断的五件事

- 历史"公司产品清单"要用公告回补(fund_manager_em 只反映当前在任)
- 公告标题解析("增聘"vs"调整"、人名提取)
- 基准中途是否修改
- 前十大消失 ≠ 卖出
- Mandate 约束抽取("不低于80%"这类语句没法自动结构化)

### 7.3 反爬

本地缓存 + 随机延时 + 失败≤3次 + 大批量走横截面接口。**不写爬虫脚本** —— 数据散在多个源且经常改版,写死的爬虫下季度就废;难的不是取数,是判断取到的数对不对。

### 7.4 Agent 自主研究

Agent **先列问题，再找数据**，不能先漫无目的抓一堆网页。来源按法定原文 → 本人原话 → 专业数据 → 正式媒体 → 社交线索递减；搜索摘要只能定位原文，不能直接成为证据。

所有材料先拆成三层：原文直接支持的事实、由事实推算的计算、Agent 给出的判断。每次研究必须保存检索日志、零结果和冲突账。网页、PDF、行情都要保留日期、口径和定位；关键冲突无法裁决时降低置信度或停止购买判断。

### 7.5 动态战役的数据纪律

战役把外部事件、经理原话、披露动作、真实 K 线和后续结果放进同一时间轴，但不强行制造因果。新闻能证明“当时发生了什么”，不能自动证明“经理为什么买”。

系统同时保留两只时钟：经理动作只能定位到相邻披露之间的区间；普通用户只能在定期报告公开后看到。报告期末不是成交日，前十大消失不是退出。没有真实 K 线或动作证据时，整场动态回放停用。

## 八、前端设计理念

### 8.1 设计原则

1. **结论先给。** 首屏就是判决(评分 + 印章 + 一句话判词),不铺垫。
2. **一个模块 = 一个判词 + 三条证据 + 一条反证。** 反证(Why We May Be Wrong)必不可少。
3. **零图表库。** 血条、对照条、瀑布、雷达全部 CSS gradient + width 过渡 + inline SVG。这是"简单易懂、能截图"的根本原因。
4. **黑白双主题。** 不是深色顺手翻白 —— 荧光绿在白底只有 1.6:1 对比度,浅色主题必须换成深橄榄绿;野兽派投影色抽成 `--brutal` 变量,深色下荧光绿、浅色下黑。
5. **全中文。** 界面搜不到裸露英文术语,全部按对照表译成大白话。

### 8.2 核心组件(辨识度来源)

| 组件 | 干什么 |
|---|---|
| 巨型分数 | 首屏评分,从 0 滚动到 78 |
| 判决印章 | "可以买"圆形公章,斜 11°,比一行字有力 |
| **对战擂台** | "他 vs 公司其他人"做成格斗画面,血条+VS块+判定 —— 全页最好玩、传播性最强 |
| 双分数对照条 | Thinking / Alpha 两条永不合并,四种判词矩阵 |
| 行为 DNA 雷达 | 10 维属性,最短那根标黄 |
| Alpha 瀑布 | 灰色=风口红利,荧光绿=真本事,颜色比例直接说明问题 |
| 动态战役回放 | 真实 K 线贯穿，新闻、持仓动作、经理原话和结果按时间推进；胜仗败仗同尺寸混排 |
| 天气图 | 4 格象限,"他在什么天气能打,什么天气挨揍" |
| 资金徽章 | 有证据点亮,无证据灰 —— 禁止猜测 |
| 机构资金流 | 6 期柱状图,谁在进谁在退 |

### 8.3 文案守则

- 面向"不知道买基金要看基金经理"的人
- 禁用:综合来看 / 值得关注 / 长期视角下 / 一方面另一方面 / 业绩优秀
- 金句必须含具体数字
- 娱乐封号只能来自行为证据(不甩锅的狼 / 规模受害者),不取笑外貌地域隐私

### 8.4 人话隔离层（硬规则）

内部编码只服务计算、校验和证据追踪，**不得直接进入用户界面**。原始 JSON 可以保留 `M01`、`P11`、`A01`、评审角色键和交易事件码；渲染前必须经过统一的人话转换层。

| 内部写法 | 页面写法 |
|---|---|
| `A01 / B03 / C01` | `2026年二季报 / 经理访谈 / 历史持仓` |
| `P11 / M20` | 不显示编号，只显示 `情绪稳定 / 独立决策` |
| `已证实 / 估算 / 未证明` | `公开资料确认 / 根据公开资料推算 / 证据还不够` |
| `people_investigator` | `人物调查员` |
| `B / H / S / EXIT` | `买入或加仓 / 继续持有 / 减仓 / 完整报告确认退出` |
| `House Consensus` | `公司主流持仓` |
| `Independent Thinking` | `敢不敢和同事不一样` |
| `Independent Alpha` | `不一样时有没有赚到钱` |
| `Alpha / Beta` | `主动赚到的钱（Alpha）/ 行情红利（Beta）` |
| `AUM` | `管理规模（AUM）` |
| `APPROVED / WATCH / DO NOT ADD` | `可以买 / 先观察 / 不要加仓` |

页面可以在中文后用括号补充专业词，不能让用户先学术语才能看懂。证据不足时直接写清“还缺什么”；来源列表显示报告全名、发布日期和“打开原文”，不显示来源编号。自动测试必须拦截裸露内部编号和禁用套话。

| 机密档案 | 给经理立案侦查 | 牛皮纸、红章、手写批注 | `此人最值钱的时候，恰恰是和公司不一样的时候` |
| 游戏卡牌 | 抽卡抽到这个经理 | 稀有卡、属性、证据翻牌 | `你抽到了一张不跟风还真能赢的卡` |
| 观点擂台 | 能买方对不能买方 | 双方血条、对战、最终裁决 | `经理能力赢了，产品风险也可能赢` |
| 体检报告 | 给经理和产品分别体检 | 化验单、医生章、风险处方 | `人没坏，产品现在有病` |
| 华尔街日报 | 财经头版审判 | 报纸大标题、人物特写、证据栏 | `把复杂尽调写成一眼看懂的头版` |

**同一套数据，七种叙事。** 数据、结论和证据必须完全一致，只允许视觉语言与叙事节奏不同。

## 十一、竞品与空白

### 11.1 为什么没人做(验证过)

五个关键词搜 GitHub,≥15 星仓库全部为 0:
`active share holdings` / `fund holdings overlap` / `portfolio crowding` / `herding institutional holdings` / `fund manager skill`

### 11.2 现有库的三个结构性盲区

1. **分析单元是"组合",不是"人"** —— 没有"他还管过别的产品""这决策他以前做过""同期别人怎么做"的概念
2. **归因是"期间可加分解",不是"事件级归属"** —— 不能把「2020Q2 低配白酒」锚定成决策并追踪 12M 后果
3. **没有"对照组"概念** —— 没有任何库支持"用同公司其他经理的持仓合成一个基准",而这正是 House Consensus 的全部内容

### 11.3 可复用

akshare(数据) / pyfolio-reloaded 的 perf_attrib(剥离因子 beta) / empyrical(单指标) / ffn(并排展示)。其余全自建。
