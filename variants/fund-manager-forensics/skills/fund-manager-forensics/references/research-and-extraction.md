# Agent 自主研究与数据提炼

## 一句话原则

**先列问题，再找数据。** Agent 的任务不是把网页搬进报告，而是把可以复核的原始材料提炼成可计算、可引用、可讲人话的事实。

## 1. 先建问题清单

每个 Deep 任务先写研究清单：当前经理和任期、逐期持仓变化、净值与基准、经理原话与真实动作、公司其他经理、赢家败仗、历史战役环境、阻止裁决的数据缺口。问题必须映射到输出字段，没有用途的数据不抓。

## 2. 来源阶梯

1. **法定原文**：基金公司公告与定期报告、证监会、交易所、政府文件、上市公司公告。
2. **本人原话**：基金公司正式访谈、持有人信、路演文字稿、权威媒体完整专访。
3. **专业数据**：净值、行情、规模和历史持仓；必须保留口径和日期。
4. **正式媒体**：还原当时舆论和市场现场，不替代法定数据。
5. **社交线索**：只用于发现关键词和原文，不进入关键结论。

搜索摘要不能作为证据正文。镜像 PDF 要标“镜像”，并继续找法定原文。

## 3. 检索动作

每个问题至少做三轮：精确对象检索、行为证据检索、反证与冲突检索。历史战役再查同期政策、行业事件、基金开放限购赎回和上市公司公告。

保存检索日志：检索词、时间、打开过的来源、采用与拒绝理由。完整检索后的零结果也要保存，不能为填满字段编造材料。

## 4. PDF、网页和行情怎么提炼

### PDF

- 记录报告全名、报告期、发布日期、页码和原句。
- 表格保留列名、单位和合计口径。
- “期末持仓”“累计买入”“累计卖出”不能混用。
- 扫描版无法提取时用浏览器逐页核对；仍读不到就登记缺口。

### 网页

- 记录标题、发布方、发布日期、段落位置、原文链接和抓取时间。
- 动态页保存稳定原文链接；只有搜索摘要时继续找原文。
- 转载内容回溯首发，无法回溯时降低等级。

### 行情与净值

- 保存代码、交易所、频率、复权方式、币种、时区、起止日和供应方。
- 日线可以聚合成周线；不能拿净值折线冒充股票 K 线。
- 数据断档时停用该图，不补画假数据。

## 5. 时间规则

- 新闻、公告和政策有精确日期时写 `exact_date`。
- 基金交易通常只有两个披露快照之间的时间区间，写 `period_window`。
- 报告期末是持仓快照，不是成交日。
- 公众只能在报告发布日期之后看到持仓，同时保留经理时钟和公众时钟。
- 日期不确定时扩大时间区间，不得用一个看起来精确的日期填空。

## 6. 事实、计算和判断分开

- **事实**：原文直接支持。
- **计算**：由事实推算，保留公式和口径。
- **判断**：Agent 对事实与计算的解释。

新闻不能证明买卖动机。只有经理本人明确连接事件与动作，才能写“因为”；否则只能写“同一时期发生”。经理说过什么和持仓做过什么必须分栏。

## 7. 可用事实

每条可用事实只表达一个意思；数字带日期、单位和口径；带 `status`、`confidence` 和来源定位；能直接进入计算或人话判词；用户文案不含内部编号。

```json
{
  "fact": "虚构示例：一季末持有示例公司100万股",
  "status": "已证实",
  "confidence": "高",
  "time_precision": "period_window",
  "source_title": "示例基金第一季度报告（虚构）",
  "source_locator": "期末前十大股票投资明细"
}
```

## 8. 冲突账

两个来源冲突时都进冲突账。比较来源等级、报告期、是否更正和统计口径；写明采用哪一个及原因。无法裁决就保留两种说法并降低置信度，影响核心结论时停止购买判断。

## 9. 网络失败与恢复

- 同一地址最多重试三次，再切同等级来源。
- 反爬、验证码或动态加载时可用浏览器读取，不绕过登录和访问控制。
- 不调用未授权生产接口，不上传本地缓存、账号信息或私有文档。
- 抓取结果先落本地缓存再提炼；失败也保存错误和待补字段。

## 10. 完成门槛

- 当前经理、任期、产品类型和最新报告期已确认。
- 45项基金取证与24项人物取证都有事实、估算或明确缺口。
- 关键收益、持仓、经理变更和合规结论至少有A/B级来源。
- 每场战役有真实行情、至少一个经理动作时间区间、至少两个外部事件和结果口径。
- 赢家与败仗同样记录；经理满意票允许零结果。
- 检索日志、零结果、冲突账和数据截止日齐全。
- 任何关键缺口都转成人话，不伪装成完整数据。
